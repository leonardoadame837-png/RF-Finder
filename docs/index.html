🎯 Overview

RF Finder is a Windows-based passive RF spectrum analysis application designed for field monitoring, signal detection, and investigation recording. It combines FFT-based spectrum analysis with threshold detection to identify RF signals and correlate them with investigation records.

Key capabilities:

  • Real-time FFT spectrum analysis with configurable resolution
  • Automatic signal detection above noise floor
  • Waterfall history for temporal signal tracking
  • GPS-tagged observation storage in SQLite
  • Investigation correlation system
  • Local authentication and session management
  • Hardware-agnostic signal source architecture (simulator default, SDR optional)

Signal Processing

FFT + Detection

Spectrum analysis, threshold detection, SNR and bandwidth estimation. Configurable FFT size, sample rate, and detection threshold.

Field Data

GPS Ready

Observations carry latitude, longitude, altitude, and timestamp metadata. Observations are stored in local SQLite database.

Evidence

SQLite + JSON

Detections and investigations persist locally. Export observations for analysis, mapping, and reporting.

Security

Local Auth

Salted PBKDF2-HMAC-SHA256 password hashing. Process-local session tokens. No cloud dependency or credentials required.

🏗️ Architecture
Signal Source (Simulator/SDR) ↓ FFT Spectrum Analyzer ↓ RF Signal Detector ↓ Power Spectrum + Detections ↓ Tactical Dashboard + Waterfall ↓ Observation Store (SQLite) ↓ Investigation Records
🚀 Quick Start

Prerequisites: Python 3.11+, Windows (primary target)

git clone https://github.com/leonardoadame837-png/RF-Finder.git cd RF-Finder python -m venv .venv .venv\Scripts\activate pip install -r requirements.txt
▶️ Run the Field Application

The default signal source is the software simulator. No hardware is required for testing.

python -m app.field

This starts the RF Finder field monitor on http://127.0.0.1:8000 with a live spectrum display, waterfall history, signal table, and investigation interface.

🧪 Run Tests
python -m pytest -q

Automated tests cover simulator lifecycle, spectrum analysis, signal detection, waterfall bounds, observation persistence, investigations, tactical API, authentication, and performance benchmarks.

🔧 Configuration

All settings are centralized in app/config.py:

Parameter Default Description
sample_rate 2 MS/s Complex IQ sample rate
center_frequency 100 MHz RF center frequency
fft_size 2048 FFT transform size
detection_threshold_db 6 dB Detection threshold above noise
minimum_signal_bandwidth_hz 10 kHz Minimum detected bandwidth
waterfall_history_frames 256 Waterfall display depth
🔐 Authentication

RF Finder requires local authentication before RF processing begins. On first run, you'll create a local administrator account. Passwords are never stored in plaintext—they use random salts and PBKDF2-HMAC-SHA256 with 600,000 iterations. Session tokens are generated with Python's secrets module and expire after one hour.

📡 Signal Sources

Simulator (Default): Software-only test signal generator. No hardware required. Ideal for development and CI testing.

SDR (Future): Optional receive-only interface for hardware like RTL-SDR, LimeSDR, or other SoapySDR-compatible devices. The architecture is designed to accept external signal sources via a clean interface. SDR support will remain passive (receive-only).

⚖️ Legal Notice

RF Finder is a passive spectrum analysis application intended for lawful use. Do not use it for:

  • Interception of private communications
  • Decryption of encrypted signals
  • Identification of private individuals
  • Unauthorized RF interference or jamming
  • Threat assessment, targeting, or evasion

RF Finder may be used for lawful purposes including spectrum monitoring, signal anomaly detection, evidence collection for investigation, Remote-ID observation, and field mapping with appropriate authorization.
